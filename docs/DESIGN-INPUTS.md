## 功能 A「让图片动起来」— 流程已定稿

参考图：`docs/design/ui-function-a-flow.jpg`（9 步 storyboard）。

1. **上传图片**：进入功能 A，上传 JPG/PNG（建议 ≥1280px，单张 ≤10MB），选择画布比例 16:9 / 9:16 / 3:4。
2. **图片加载完成**：图片显示在画布中，可开始框选。顶栏：画幅 / 分辨率 / 时长 / 预览。
3. **框选区域**：鼠标在图片上直接拖框，框住想让它动的区域（显示尺寸如 320×120）。
4. **选择动画效果**：二级结构——先选大类（出现 / 强调 / 移动 / 放大 / 标记 / 消失），再选具体效果（如 强调→弹一下 / 轻震 / 放大一下 / 高亮 / 描边 / 颜色变化）。
5. **实时预览效果**：设置后画布即时预览；可调速度（慢/正常/快）与持续时间（秒）。
6. **添加多个动画**：继续框选其他区域，为不同元素分别添加动画（画布上标序号 ①②③）。
7. **调整动画顺序**：右侧「动画列表」拖动排序；先后关系用「同时 / 接着 / 稍后」表达，不做传统时间轴、不做关键帧编辑器。
8. **全局设置与预览**：整体时长、完整效果预览（播放器形态）。
9. **生成高清 MP4**：提交 GitHub Actions 云端渲染，页面显示进度（准备素材→渲染→生成 MP4→完成），完成后下载；产物保留 24–48 小时后自动删除。

关键产品决策：
- 功能 A **第一版不强迫 AI 参与**——用户面对自己设计的图，框选比 AI 判断更快。
- 动画效果对用户暴露的是「可理解的大类 + 少量二级效果」，不是技术名称清单。
- 顺序调整只有「同时 / 接着 / 稍后」+ 每动作「快 / 正常 / 慢」，系统换算成真实 timeline。

## 已从讨论中确认的方向性共识（供开发时参考，非新需求）

- 动画系统三层：Meaning → Beats → Structure → Actions；timeline 由系统计算，不由用户/AI 手排。
- AI 导演职责：理解内容 → 删减文字 → 判断关系 → 拆 beats → 选结构 → 选重点 → 选动画能力；**不碰坐标**，排版引擎负责布局。
- 首批信息关系结构（Layer 2）：对比 / 流程 / 递进 / 发散 / 汇聚 / 重点；一个画面 = 一个主结构 + 若干局部关系 + 一组基础动作，不是单一模板。
- V1 不做：3D、粒子、毛玻璃、大面积动态模糊、复杂 morph、任意 SVG 手写、音频驱动。
- 不做「输入→spec」训练数据存储（与即用即弃、不建数据库原则一致）。
