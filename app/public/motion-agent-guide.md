# Motion 视频策划与交接规范 V0.2.0

适用位置：Motion 项目内的「画面安排 → 导入制作总表」。这不是「素材工具 → 文字图解动画」的独立图解方案格式。

获取入口：Motion「制作规范」页面，或只读 MCP 的 `list_guides` / `read_guide`。规范接口不读取私人项目；最终稿由用户在对话提供，或通过用户主动创建的项目交接读取。

## 给新对话的任务

请根据用户提供的最终口播稿，独立策划可由 Motion 执行的视频画面，交付一份制作总表 JSON、简短自查结果及待补素材清单。先阅读本规范，再判断稿子的重点和叙事节奏。不要询问用户的 Motion 项目编号、版本或所谓“制作资料”。不要假装访问过 Motion、Workspace 或 WorkPrint。

本规范不是某篇稿子的标准答案；不要预设幕数、画面比例、录屏数量或总时长。不需要参考上一位 Agent 的总表。

## Agent 交接入口

日常建议：用户与ChatGPT完成终稿后，由Codex/WorkBuddy等有工具执行能力的Agent统一负责策划、查证素材、检查和提交。不要求用户先在普通聊天制作一次再交给Agent补做。

如用户提供项目交接密钥：先调用read_project读取当前项目终稿与revision，再读取本规范；完成后用submit_plan提交plan和expectedRevision。接口使用与网页相同的真实导入校验，失败应修复后再提交。提交仅进入待采用状态，用户在Motion采用后才替换项目画面。不要声称上传JSON文件是必要操作。

交接密钥只授权单个项目，24小时有效；不含媒体文件传输权限，不可公开或写入源码。项目读写是用户主动建立的临时交接，不是全站云同步。录音和媒体传输尚未接通。无密钥时仍可使用独立终稿策划及JSON文件导入方式，不向用户索取内部项目编号。

## 1. 先独立判断，再编排

1. 确认拿到的是最终稿，明确该稿的表达目标、受众、语气和论证转折。用户已给出的信息不要重复索取。
2. 按意思与视觉任务分幕，不按 PDF 行数或每句机械切镜。长解释可用多幕展开，连续论证可共享一幕；不能为了凑数量重复做卡片。
3. 优先用可核实的实际操作解释案例；没有实际文件时，只能提出具体的待录制方案，不能写成已经取到素材。不要为了“动态”滥用昂贵生成视频。
4. 让图解承担对比、步骤、要点或强调的任务；画面文案提炼信息，不整段照搬口播，也不把推论改写成用户事实。
5. 对每幕给出可执行的画面、对应原文、所需素材、准备成本与替代方式。只把 Motion 能执行的参数写入执行字段。额外拍摄建议、来源说明属于备注，Motion 不会自动执行。

### 画面质量与可执行性检查

- 章节大纲不等于视频分幕。一幕只承载一个可以由当前模板完成的视觉任务。若一幕覆盖多个论证转折或案例，应拆分；不凭固定幕数或强制秒数凑镜头。
- 没有现成录屏，不等于不策划录屏。先判断实际操作是否比图解更清楚，再给出具体待录动作、文件名、对应原文、准备成本和替代方案；不能把所有案例自动降级为文字卡片。
- 逐幕核对：Motion实际执行的是kind/template/items等字段。备注中的“名词堆叠”“成本账单”“关系图”“慢慢展开”等自然语言不会变成额外动画。若现有模板无法执行，改成可执行分幕或提出待录素材。
- 对比标题必须准确描述这一次比较，不能把“传统路径/问题驱动”套在自动化/Agent、模型/执行环境等无关比较上。
- 给出跨度明显较大的幕及判断依据（如覆盖的多个主题、转折、原文字数）；不编造朗读时长。成片节奏在真实录音同步后复核。

## 2. 谁做什么，何时需要录音

| 环节 | 责任方 | 输入与输出 |
|---|---|---|
| 定稿 | 用户与 ChatGPT | 用户确认的最终文字 |
| 策划 | ChatGPT 或其他 Agent | 根据最终文字生成本规范的 JSON；使用该 Agent 的订阅额度 |
| 导入检查 | Motion 普通程序 | 核对全文、结构、编号、覆盖及素材引用；自动绑定当前项目；不调用 AI |
| 录音与同步 | 用户录音；Motion 接收时间 | 画面策划无需录音；预览/渲染需要真实时间。目前可导入实际录音的时间字幕；程序按内容建议画面时间，允许语气词/不同分句，低匹配、跨幕边界需试听确认。云端粗剪可转写实际录音，需先完成私有任务授权及禁止超额付费设置 |
| 取材 | Agent 选择与核实，用户或已授权工具交接文件 | Workspace 是文字/文件依据，不是视频库。Motion 规范只读 MCP 已提供；WorkPrint 自动取材及 Motion 媒体读写 MCP 尚未接通；项目文字可经用户临时交接密钥读写 |
| 预览与渲染 | Motion 程序执行 | 缺时间或文件的段落不得冒充就绪；云端用量受账户免费配额限制，不是无限免费 |

录音只需先交给 Motion。策划 Agent 不必再收一遍录音；如果后续另请 Agent 负责听音对齐，该阶段才需要录音或真实字幕，并另行说明如何交接。策划稿的 start/end 一律为 null，不按字数、预估语速或“约13分钟”填写秒数。

## 3. 当前能执行的画面

| kind | 能力 | 限制 |
|---|---|---|
| info | 程序文字图解 | template 只支持 focus、steps、comparison、list；不生成任意HTML/JS，不自由绘制复杂关系图 |
| image | 背景图片＋独立图片/文字元素动画 | 背景 motion 为 still、push、pan；layers 支持元素出现、位移、缩放、透明度、旋转。需要分别上传元素文件，不会自动抠图 |
| video | 已有录屏/视频按入点播放 | 需要真实文件；sourceIn 是原文件入点秒数。此阶段尚无录音，默认0，不猜应截多少秒 |

focus 强调一个主题，可有1—6项短文字；steps 依次出现步骤；list 展示要点；comparison 左右对比，items 必须恰好两项，并填写 leftLabel/rightLabel。每幕最多6项，建议更少；标题与条目应短而清楚。不同模板的视觉变化有限，不应承诺自定义动画。

独立图片局部动画工具与独立六结构图解工具，不会自动执行项目总表中任意局部指令。当前也未一键互通；不要把它们当成项目模板。

## 图片画面制作流程（V0.2.0）

用户需要有内容、有变化的画面，不能用两行摘要撑住整段口播。先策划视觉事件，再选模板。新增字段可与旧总表共同使用；格式 version 仍为1。

1. 确定全片 visualStyle：画风、配色、人物/物件外观、构图和比例。先做少量样板，经视觉确认再批量；文字约束不能保证所有图片自动一致，生成时复用已认可的参考图。
2. 逐幕写 visualBrief：画面具体出现什么、先后如何变化、如何解释这段话。复杂段落可拆幕，不固定幕数。真实工具演示仍优先真实录屏，不用生成图片冒充实际软件或历史证据。
3. image 幕用 imagePrompt 描述背景；layers 中图片元素各写 prompt，安排背景和透明 PNG 元素分别生成，避免背景已经画了同一元素而出现重影。重要中文由 Motion 文字元素呈现。
4. 配图在 ChatGPT 等有图像生成能力的工具中完成；使用相应订阅的可用额度，不能承诺无限免费。Motion 不调用付费图片 API。用户或可操作文件的 Agent 上传图片并连接 assets；临时交接 MCP 仍不传输图片字节，参考图也需实际提供给生成工具。
5. 上传后导入总表或逐幕元素方案，预览动画，再结合真实录音复核节奏。生成缺失时明确待补，不能把提示词当成图片。原文单元 start/end 仍为 null；已有项目同步时间不能无依据重写。

顶层可选 visualStyle：不超过6000字的全片风格说明。每幕可选 visualBrief（画面变化说明）、imagePrompt（背景配图提示词）。这些说明不自动执行；只有下面的 layers/keyframes 执行动画。Motion 的“画面安排 → 统一画面风格与配图”可下载配图任务清单，并上传图片。

仅 kind:image 可加 layers 数组（最多24个）。每层：
- id：本幕内唯一，英文字母/数字/下划线/连字符，最多80字符；kind:image 或 text；label：元素名称。
- image 层：assetId 必须引用 assets 中 kind:image 的条目；可选 prompt 为生成提示词。text 层：text 为1—300字，不需要图片文件。
- x/y：中心点位置，占画面宽高百分比，范围 -100—200，默认50；width/height 为画面百分比1—100，默认35/25。图片完整缩放放入此框，不拉伸；后面的层覆盖前面的层。
- fontSize：文字字号12—120，默认48；color：六位十六进制色值，默认 #252b2a。
- start/end：**本幕进度0—1**，默认0/1，end 必须大于 start。它们不是录音秒数。比如0.5表示该幕真实时间的中点，不是假定整段时长。
- keyframes：最多12个，at 严格递增且在 start/end 内；可写 x/y（同上）、scale（0.05—5）、opacity（0—1）、rotation（-360—360）。缺失属性沿用上一节点；无节点则静态呈现。程序平滑插值，支持前后跳播，单段与完整导出一致。
- 出现和结束默认直接显示/隐藏；需要淡入淡出时显式给 opacity 节点。避免把长解释只安排成开头淡入然后静止。

以下为一幕 image 的 layers 示例（还需完整幕字段、背景 assetId 及对应 assets）：

```json
[
  {"id":"bubble","kind":"image","label":"冒出的新问题","assetId":"BUBBLE","prompt":"统一蓝黄纸片插画风，一个空白对话气泡，透明背景PNG，无文字","x":30,"y":45,"width":28,"height":25,"start":0,"end":1,"keyframes":[{"at":0,"opacity":0,"scale":0.8},{"at":0.15,"opacity":1,"scale":1},{"at":0.75,"x":65},{"at":1,"x":65,"opacity":0}]},
  {"id":"caption","kind":"text","label":"关键概念","text":"越聊，问题越多","x":50,"y":75,"width":65,"height":15,"fontSize":48,"color":"#252b2a","start":0.25,"end":0.9,"keyframes":[{"at":0.25,"opacity":0},{"at":0.4,"opacity":1}]}
]
```

逐幕设置也支持导入独立元素方案：`{"version":1,"backgroundAssetId":"BG","layers":[...]}`。此方式要求图片已经上传，使用该项目素材编号；不替代包含全文的制作总表。

当前不是生成视频模型：不能自动让平面人物走路、自动分割一张图或补出遮挡区域。分层动画与独立“图片局部动画”工具各自保留，不会互相自动转换。生成样图、连好素材、实际预览和渲染是不同完成状态，交接时必须分别说明。

## 4. 可直接导入的格式

输出 UTF-8 的纯 JSON 文件，不加代码围栏、注释、尾随逗号或省略号。用户将它拖入项目的「导入制作总表」。

顶层：
- version：固定1。
- binding：固定 "script"。
- sentences：按全文顺序排列的完整原文单元，1—5000个。可按语义拆分并合并 PDF 断行，不能删改原文和标点。
- assets：图片/视频文件清单；没有就填 []。
- scenes：按视频顺序排列的1—500幕。
- 不提供 projectId、audioRevision、scriptRevision。它们由 Motion 在匹配原文后关联，Agent 不得编造或索取。
- 可加 planningNotes 字符串数组记录整体风险；场景的 recordingInstructions（补录动作）、fallback（替代方案）、sourceStatus（来源状态）会保存并显示在画面卡片的“素材准备与替代方案”，也可在画面设置编辑。它们是说明，不是动画指令，替代方案不会自动执行。

原文单元：
- id：唯一字符串，仅英文字母、数字、下划线和连字符，1—80字符。
- text：非空原文。所有 text 按顺序拼接后，必须与用户终稿完全一致；只允许空格与换行差异。不得统一标点、替换同义词、简繁转换或改写“更通顺”。
- start、end：本阶段必须显式为 null。

每幕：
- id：唯一，规则同原文编号。
- title：1—200字，写有意义的画面主题；实际标题应简短。
- sentenceIds：引用连续原文单元，按原文顺序排列。全文每个单元恰好出现一次；幕与幕顺序不能倒置。
- kind：info / image / video。
- template：focus / steps / comparison / list。图片/录屏可统一填 focus。
- items：字符串数组。info 为1—6项非空文字；comparison恰好2项。图片/录屏可为 []。
- leftLabel、rightLabel：左右标签；非对比幕也可填“之前”“现在”。
- sourceIn：非负数字；无素材填0。
- motion：still / push / pan；非图片幕填 still。
- focusX、focusY：0—100的数字，通常均为50。
- assetId：image/video必填，必须指向assets中类型匹配的编号；info不填。

素材条目：
- id：唯一，限英文字母/数字/下划线/连字符，建议不超过80字符。
- name：唯一的文件名，不含路径或URL。例如“客户表演示.mp4”。不要把文件地址当成已连接素材。
- kind：image 或 video。
- 已有文件和待补文件都可列清单，但必须在交付说明中区分。待补文件导入后仍然缺素材，不能直接渲染该幕。
- 建议图片PNG/JPG/WebP，视频MP4。避免私有客户、账号、邮件及未授权内容入镜；可以明确安排合成示例，但不能冒充历史证据。

### 中性格式示例（仅演示结构，不是用户稿件的策划答案）

```json
{
  "version": 1,
  "binding": "script",
  "sentences": [
    {"id":"S001","text":"今天重复整理表格。","start":null,"end":null},
    {"id":"S002","text":"想把它变成一键操作。","start":null,"end":null}
  ],
  "assets": [],
  "scenes": [
    {
      "id":"SC001",
      "title":"想改变的操作",
      "sentenceIds":["S001","S002"],
      "kind":"info",
      "template":"comparison",
      "items":["重复整理","一键完成"],
      "leftLabel":"现在","rightLabel":"希望",
      "sourceIn":0,"motion":"still","focusX":50,"focusY":50
    }
  ]
}
```

## 5. 不把新风险藏起来

- 没有完整终稿：只索取最终稿，不要求用户导出 Motion 内部资料。
- PDF有页码、标题、篇幅说明：检查它们是否混入提取文字。不能擅自删除后声称可匹配现有项目；策划阶段保留原文并注明版式文字。同步候选中可以由用户明确标记整幕“未朗读，不单独出画面”；混合了正文的幕不能整幕跳过。原终稿不改，导出字幕使用实际录音字幕；未匹配部分必须人工确认。
- 看不到素材：标记待补，写明确录屏动作和无素材替代方案。若实际案例依赖核验，不虚构Workspace记录或WorkPrint视频。
- 需要未实现的画面：改用现有图解/实录，或标成未来建议，不把任意导演指令塞给执行器。
- 导入失败：报告是哪一幕/字段/原文差异；不要随意删除原文、填假时间或换项目编号来绕过校验。
- 尚未验证的混合成片、页面视频回传或10—20分钟渲染：明确待验，不把总表导入成功当成完整视频成功。

## 6. 交付前自查

必须交付：
1. 制作总表JSON文件（全文，不是节选/占位）。
2. 简短摘要：幕数，各kind数量，待补素材及原因；不提供虚构秒数。
3. 已查项目：原文一致、全部覆盖、无重复引用、连续且顺序正确、模板可执行、素材引用完整、时间均null。
4. 仍未查项目：没有实际文件/录音/浏览器或代码执行能力时，明确说明。未经运行不得说“已通过Motion测试”。

有代码环境时，用项目内 scripts/validate-production-plan.mjs 对原文TXT和JSON执行真实导入校验：在项目根目录运行 `node scripts/validate-production-plan.mjs --script 最终稿.txt --plan 制作总表.json`。需先安装 app/package.json 的依赖。没有执行环境就按规范自查并标注“未运行程序校验”。

## 7. 新方案的验收与比较

先过硬性门槛：格式、全文一致与唯一覆盖、支持的模板/参数、素材引用和时间规则。未过门槛先修复，不凭“画面创意好”算可执行。

再比较内容质量：是否抓住表达重点；画面是否补充口播而非照稿念；关键案例是否具体真实；图解/录屏节奏是否合适；需要用户准备多少材料；缺素材是否有可执行替代；哪里比另一份更清楚，哪里更费力。

不把任何旧总表当标准答案，不因幕数相同、图解更多或录屏更多加分，不强求某一比例。分别列“导入已验证”“渲染待验证”“编辑判断”，不混为一个总分。初版规则需随真实测试修订，不宣称已经完成跨Agent验收。

## 8. 实际口播与终稿不一致时

用户处理完音频后，以最终音频为唯一时间基准。导入来自这份音频的SRT/VTT；无时间的文本不能生成真实时间。程序按文字内容匹配现有画面，不要求分句一致；语气词、少量替换会影响匹配置信度，低匹配/字幕跨幕/缺读均要核对，不伪造准确时间。采用后保留完整终稿和画面内容，把原文锚点按幕合并；字幕独立保存为实际口播文字。已对齐后再改分幕需重新检查。

当前录音粗剪入口可通过私有云端任务识别实际录音。分析不改变音频，只有用户选择并确认的区间才会执行剪切；不要把转写与字幕修改冒充已经完成音频剪切。


## 录音粗剪与时间同步

策划阶段仍只依赖终稿，不编造时间。录音阶段可以先粗剪，再用粗剪后的真实录音同步画面。

- Motion 云端粗剪先查长停顿和疑似重读，候选默认未选。只有用户确认的区间才会删除。清嗓子、错读和呼吸不保证能自动识别。
- 生成粗剪音频不会替换主音轨；试听并点击采用后才替换，原录音保留，可恢复。
- 采用或恢复录音会清除旧画面时间和旧字幕绑定。根据当前录音的实际转写重新建议时间，低匹配和未朗读内容仍需确认。不得按字数估时。
- 使用开源 FFmpeg 与 faster-whisper，云端执行，本机不运行语音模型，不调用付费 AI API。GitHub 私有任务使用账户配额；启用前须确认账户已禁止超额付费，Motion不能自动验证计费设置。
- 执行任务权限只读，产物保留1天。输入位于私有任务分支，分支与运行记录不会自动清理。不得声称所有数据自动删除或无限免费。
- 粗剪不负责最终声音精修；完整视频导出后可在剪映做最终调整。
